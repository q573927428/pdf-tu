# PDF 目录提取与图片转换方案

## 1. 目标

建立一个可重复运行的 Python 工具，递归扫描：

`F:\\ipkaishi\\zhixiaoman\\幼升小.zip\\幼升小`

对所有子目录中的 PDF：

1. 提取 PDF 标题（默认使用文件名去掉 `.pdf`；可选读取 PDF metadata title）。
2. 生成目录表格，固定包含九列：年级、学期、PDF 文件名称、PDF 文件所在位置、转换后的图片 1 至转换后的图片 5。
3. 每个 PDF 只渲染前 5 页；少于 5 页时渲染全部页面。
4. 对输出图片按配置添加水印，水印可开关。
5. 支持重复执行、断点复用、错误记录和最终汇总。

当前源目录已发现约 579 个 PDF。路径必须按绝对路径处理，避免工作目录变化导致结果漂移。

## 2. 输出目录与表格

建议输出结构：

```text
output/
  images/
    math/<category>/<pdf-stem>/page-01.png
    chinese/<category>/<pdf-stem>/page-01.png
  pdf_catalog.xlsx
  pdf_catalog.csv
  errors.csv
  run.log
```

输出目录、图片目录和生成文件名均使用英文或 ASCII；源目录和表格中的原始中文文件名、业务字段值保持不变。源目录中的中文分类名映射为安全化的 ASCII 目录名（例如 `数学` -> `math`、`语文` -> `chinese`），无法映射的字符使用短哈希补足，避免重名覆盖。

表格列定义：

| 列 | 内容 | 规则 |
|---|---|---|
| 年级 | `幼升小` | 本批次固定值，后续从配置读取 |
| 学期 | `全册` | 幼升小默认值；高年级从 `上册`/`下册` 目录自动识别 |
| PDF 文件名称 | 文件名或 metadata 标题 | 默认文件名 stem，保留中文 |
| PDF 文件所在位置 | PDF 绝对路径 | 使用 Windows 原始路径写入 |
| 转换后的图片 1~5 | 图片路径 | 仅填实际生成页数，缺少页留空 |

图片路径建议写成相对于 `output` 的路径，便于移动整个结果目录；如需在 Excel 中直接打开，可改为绝对路径配置。

## 3. 核心处理流程

```text
加载 YAML 配置
  -> 校验 source_root/output_root、dpi、max_pages、水印参数
  -> os.walk/rglob 递归查找 *.pdf（大小写不敏感）
  -> 按稳定排序（相对路径排序），按 max_pdfs 截取测试批次
  -> 读取 PDF 页数和 metadata
  -> 选择标题：metadata.title（可选且非空）或文件名 stem
  -> 渲染 page_index = 0 .. min(page_count, 5)-1
  -> 按开关叠加 RGBA 水印并保存 PNG
  -> 组装九列表记录
  -> 写入 XLSX（冻结首行、自动筛选、列宽、超长文本换行）和 UTF-8-SIG CSV
  -> 写入错误清单与汇总日志
```

使用 `PyMuPDF`（`fitz`）渲染 PDF：`page.get_pixmap(matrix=fitz.Matrix(scale, scale), alpha=False)`，其中 `scale = dpi / 72`。页面按原始顺序编号，文件名使用 `page-01.png` 形式，避免排序错误。

### 测试批次限制

前期测试不必转换全部 PDF。在 `config.example.yaml` 中设置：

```yaml
processing:
  max_pdfs: 20
```

程序先按 PDF 相对路径排序，再只处理前 `max_pdfs` 个文件，因此每次测试结果稳定、可复现。设置为 `null` 表示不限制，执行全量处理。命令行也可临时覆盖：

```powershell
pdf-catalog run --config config.example.yaml --limit 5
pdf-catalog run --config config.example.yaml --limit none
```

测试阶段建议先用 `--limit 5` 验证表格、1~5 页 PDF 和水印效果，再逐步扩大到 20、100，最后使用 `none` 做全量运行。

## 4. 水印设计

配置示例：

```yaml
watermark:
  enabled: true
  text: "幼升小"
  opacity: 90
  position: "bottom_right"
  font_size: 28
```

实现建议：

- 用 Pillow 在独立透明图层绘制文字，再与页面图像合成。
- `enabled: false` 时完全跳过水印图层，确保原图视觉不变。
- 支持 `bottom_right`、`bottom_left`、`center` 三种位置；边距固定为图片短边的 3%。
- 优先加载配置的中文字体（如 `C:\\Windows\\Fonts\\msyh.ttc`），找不到时记录警告并使用可用字体。
- 水印文字、透明度、字体大小均做范围校验，透明度限制在 0~255。

## 5. 配置与年级/学期扩展

所有路径和策略放入 YAML，不在代码中硬编码。当前幼升小使用：

```yaml
grade: "幼升小"
semester: "全册"
```

切换到一年级、二年级或三年级时，复制一份配置文件并修改源目录、输出目录和年级。例如二年级：

```yaml
source_root: "F:\\ipkaishi\\zhixiaoman\\二年级.zip\\二年级"
output_root: "./output-二年级"
grade: "二年级"
semester: "全册"
```

高年级目录通常包含 `上册`、`下册` 一级目录，程序会根据 PDF 相对 `source_root` 的路径自动填写学期、科目和分类。例如 `二年级\\下册\\数学\\奥数思维\\练习.pdf` 对应学期=`下册`、科目=`数学`、分类=`奥数思维`。没有册别目录的幼升小使用默认值 `全册`。

后续一至三年级只需改配置或增加批次配置：

```yaml
grade: "一年级"
semester: "上学期"
```

如一个目录混合多个学期，增加 `rules` 按相对路径前缀匹配，并让更具体的规则优先；未匹配项回退到默认值。

## 6. 幂等、异常与性能

- 输出文件名由 PDF 相对路径的安全化 stem 加短哈希组成，避免不同目录下同名 PDF 覆盖。
- 若目标图片已存在且源 PDF 的修改时间、大小未变化，则跳过渲染；配置变化（DPI、水印文本、开关）应使缓存失效。
- 单个 PDF 损坏、加密或某页渲染失败时，不中断全批次；在 `errors.csv` 记录路径、阶段、异常信息。
- 先写临时文件，成功后原子替换，避免中途终止留下半成品。
- 579 个文件建议串行处理以控制内存；后续可增加受限线程池，但不要并发打开过多大 PDF。
- 每次运行输出统计：发现数、成功数、跳过数、失败数、生成图片数、耗时。

## 7. 命令行接口

建议提供三个子命令：

$env:PYTHONPATH = "src"

```powershell
pdf-catalog scan --config config.example.yaml                    # 仅生成表格，图片列为空
pdf-catalog convert --config config.example.yaml                 # 仅转换图片并更新表格
pdf-catalog run --config config.example.yaml                     # 扫描、转换、输出全部结果
pdf-catalog run --config config.example.yaml  --limit 2          # 扫描、转换、输出全部结果 限制本次处理的数量
```

可选参数：`--no-watermark` 临时关闭水印、`--max-pages 5` 覆盖页数、`--limit N|none` 限制本次处理的 PDF 数量、`--dry-run` 只列出待处理文件、`--log-level DEBUG` 输出详细日志。

## 8. 验收标准

1. 递归结果包含所有扩展名大小写变体的 PDF，数量与人工抽查一致。
2. 每行年级为 `幼升小`、学期为 `全学期`，路径与源文件一一对应。
3. 1~4 页 PDF 只生成对应数量图片，5 页及以上恰好生成 5 张。
4. 水印开关分别运行后，关闭版本无水印，开启版本在指定位置可见且不遮挡主体内容。
5. XLSX/CSV 可正常打开，中文无乱码，图片列与实际文件存在性一致。
6. 任一坏文件不会阻塞其他文件，`errors.csv` 可定位失败原因。
